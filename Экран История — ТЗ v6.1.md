# WYRD — Экран «История»

## Техническое задание v6.1

Это ТЗ описывает переработку существующего экрана **«История»**.

Важно: это не новый отдельный экран. Это тот же экран, который сейчас открывается с главного экрана через кнопку **«История»** и показан на референсных скриншотах.

Рабочее ритуальное название новой версии экрана: **«Следы в лесу»**.

Решение о переименовании кнопки на главном экране принимается отдельно. До отдельного решения навигационный пункт может оставаться **«История»**, а заголовок внутри экрана может быть **«Следы в лесу»**.

---

## 1. Концепция экрана

Экран «История» в новой версии не должен ощущаться как журнал действий, список раскладов или трекер привычек.

Он становится архивом памяти леса.

Здесь остаются:

- первые карты дня — **Следы**;
- редкие знаки леса — **Дары**.

Экран должен ощущаться как коллекция найденных артефактов, а не как история активности пользователя.

Вдохновение:

- сетка карт TwoDots: равнозначные ячейки без иерархии;
- визуальный язык Veil: карты как артефакты, дата под картой;
- существующий визуальный стиль WYRD.

---

## 2. Главная механика

### Один день — один След

След дня = первая карта, открытая через экран Колоды.

Путь всегда один:

Главный экран → Войти в лес → Колода → касание колоды → расклад на 1 карту.

Если пользователь получил первую карту дня — создаётся След.

Если в этот день След уже существует — новый След не создаётся.

Расклады на 3 и 5 карт:

- не создают След;
- не попадают в историю;
- не отображаются в сетке.

---

## 3. День и timezone

След создаётся по локальному дню пользователя на момент открытия карты.

При создании Следа сохраняются:

- `dayKey`;
- `timezone`.

`dayKey`:

```ts
dayKey: string // YYYY-MM-DD, сформирован по локальному времени пользователя в timezone
```

`timezone`:

```ts
timezone: string // IANA timezone, например Europe/Moscow
```

Важно: `dayKey` нельзя формировать через UTC-дату вроде:

```ts
new Date().toISOString().slice(0, 10)
```

Такой способ может создать неправильный день вечером, ночью или при смене часового пояса.

---

## 4. Хранение истории

История является живым архивом пути.

Следы старше трёх месяцев постепенно уходят из памяти леса.

Экран не предназначен для бесконечного накопления данных.

Поэтому отображаются только записи последних трёх месяцев.

MVP допускает автоматическую очистку старых Следов после сохранения нового Следа.

---

## 5. Архитектура хранения

Экран не зависит от конкретного способа хранения данных.

Следы и Дары должны работать через простой storage-layer.

На этапе MVP допускается:

- `localStorage`.

В будущем могут использоваться:

- `IndexedDB`;
- `Convex`;
- `Supabase`;
- `Telegram Cloud`.

UI экрана не должен обращаться к `localStorage` напрямую.

Не нужно вводить enterprise-слой Repository/Service прямо в ТЗ. Достаточно практичного модуля хранения с чистым интерфейсом.

---

## 6. Snapshot текста

История хранит слепок данных на момент создания Следа.

Если тексты или название карты изменятся в будущем — старые Следы продолжают показывать исходную версию.

Для этого внутри объекта Следа сохраняются:

- `cardTitle`;
- `oracleMessage`;
- `shadowMessage`.

---

## 7. Инварианты домена

- В одном `dayKey` может существовать только один След.
- След создаётся только из первого расклада на 1 карту через Колоду.
- Расклады на 3 и 5 карт никогда не создают След.
- Фаза луны вычисляется один раз и сохраняется.
- Архивный След всегда использует `snapshot`.
- Логика Даров не управляет UI напрямую.
- UI никогда не показывает прогресс серии.
- UI никогда не показывает streak counter, progress bar, XP, уровни или `собрано X/Y`.

## 10. Вводный блок

Всегда отображается.

Текст:

```text
Следы в лесу
Один день — один след. Здесь остаётся первое послание дня.
```

Визуально:

- без рамок;
- без карточек;
- без декоративных контейнеров.

Это часть ритуального языка WYRD.

## 11. Полка Даров

Раздел Даров отображается отдельно от Следов.

Заголовок раздела:

```text
Дары леса
```

Подзаголовок:

```text
Лес иногда оставляет не ответы, а знаки.
```

### Что такое Дар

Дар — знак того, что лес заметил постоянство пользователя.

Дар не является:

- наградой;
- достижением;
- ачивкой;
- прогрессом.

Дар случается.

### Когда появляется Дар

После 7 дней подряд с сохранённым Следом пользователь получает Дар.

Пользователь никогда не видит:

- progress bar;
- streak counter;
- осталось N дней;
- собрано X/Y.

### Триггер анимации

Анимация получения Дара происходит не в момент расклада.

После создания Дара сохраняется:

```ts
pendingReveal: true
```

При следующем открытии экрана «История» / «Следы в лесу»:

- запускается анимация;
- флаг сбрасывается.

Логика:

Пользователь приходит в лес и обнаруживает, что что-то изменилось.

### Анимация появления Дара

Последовательность:

- интерфейс слегка затемняется;
- появляются золотые частицы;
- карта Дара медленно проявляется;
- карта плавно занимает место на Полке Даров.

Без:

- попапов;
- поздравлений;
- achievement language.

Это отдельный визуальный язык мира WYRD.

## 13. Структура Дара

Дар состоит из двух сторон.

Лицевая сторона у каждого Дара уникальная.

Оборотная сторона у всех Даров использует единый шаблон.

### Лицевая сторона

Содержит:

- визуальный символ;
- название.

### Оборотная сторона

Оборот является не второй иллюстрацией, а тихим паспортом найденного знака.

Визуальная композиция всегда одинаковая.

Меняются только:

- название;
- маленький фрагмент лицевой стороны;
- короткая подпись;
- дата обретения.

Композиция:

```text
Название Дара

маленький фрагмент лицевой стороны

короткая подпись

Обретено дата
```

Пример:

```text
Лунная

маленькая веточка с одной фазой луны

Луна не спешит менять форму.
Всему своё время.

Обретено 29 мая
```

Дар не содержит:

- инструкций;
- практик;
- чек-листов;
- длинных текстов.

Дар является знаком леса.

Оборот должен быть тихим и минималистичным.

Использовать:

- тёмный фон;
- тонкую золотую рамку;
- слабое внутреннее свечение;
- маленький фрагмент лицевой стороны как отпечаток Дара;
- один деликатный разделитель при необходимости.

Фрагмент лицевой стороны должен:

- занимать 5–10% композиции;
- быть тихим и не конкурировать с названием;
- сохранять связь с лицевой стороной;
- не выглядеть как самостоятельная иллюстрация.

Не использовать на обороте:

- сложные орнаменты;
- мандалы;
- перегруженные декоративные рамки;
- много золота;
- большие иллюстрации;
- achievement language.

Для даты использовать термин:

```text
Обретено
```

Не использовать:

- Получено;
- Выдано;
- Награда.

### Механика просмотра Дара

Тап по карте на Полке Даров:

лицевая сторона → плавный flip → оборотная сторона.

Повторный тап:

оборотная сторона → flip → лицевая сторона.

Использовать ощущение физической карточки.

Не использовать:

- bottom sheet;
- модальные окна.

Анимация:

```css
transform: rotateY(...);
duration: ~400ms;
ease-in-out;
```

Поддерживать `prefers-reduced-motion`.

При активном `reduced motion` использовать упрощённую анимацию без 3D-переворота.

## 14. Layout Полки Даров

Полка представляет собой горизонтальный скролл.

Если у пользователя существует только один Дар:

- показывать его как отдельный центральный объект;
- не прижимать к левому краю;
- сохранять ощущение редкости и значимости находки.

Если Даров два и больше:

- использовать горизонтальную Полку Даров;
- пользователь листает коллекцию свайпом.

Пользователь может свободно листать Дары вправо и влево.

На экране одновременно видно:

- 2–3 карты полностью;
- часть следующей карты.

Следующий Дар никогда не показывается полностью.

Пользователь видит только край или часть следующего артефакта.

Карты постепенно уходят за границы экрана и растворяются в затемнении контейнера.

Полка должна создавать ощущение, что коллекция продолжается дальше видимой области.

Ощущение:

не альбом достижений, не карусель карточек, а длинная полка найденных артефактов, уходящая в темноту.

Между картами много воздуха.

Свайп является основным способом навигации.

Не использовать:

- стрелки;
- пагинацию;
- точки-индикаторы;
- любые элементы вида ● ○ ○ ○.

Сортировка Даров:

- от новых к старым.

Новый Дар всегда отображается первым.

## 15. Сетка Следов

### Общая логика

Следы отображаются единой сеткой.

Не создавать разделы:

- Сегодня;
- Раньше;
- Эта неделя;
- Этот месяц.

Новая запись всегда отображается первой.

Сортировка:

- от новых к старым.

### Layout

MVP:

- 3 колонки;
- `aspect-ratio: 3 / 4`;
- `gap: 12px`;
- lazy loading изображений.

Все карточки имеют одинаковый размер.

Masonry layout не использовать.

Изменение количества колонок принимается отдельным решением после тестирования на реальном устройстве.

### Карточка Следа

Содержит:

- иллюстрацию карты;
- название карты;
- дату;
- фазу луны.

Не содержит:

- Послание;
- Тень;
- вопрос пользователя.

## 16. Открытие Следа

Тап по карточке Следа открывает архивный артефакт.

Использовать существующий экран результата расклада на 1 карту.

Не создавать отдельный экран просмотра Следа.

Использовать существующий компонент:

```text
CardArtifact
```

След использует тот же визуальный язык, что и расклад на одну карту.

Ощущение:

пользователь открывает найденный артефакт из архива леса.

## 17. Архивный артефакт Следа

Содержит:

- иллюстрацию;

- дату;

Тексты берутся только из сохранённого `snapshot`.

{

## 22. Acceptance Criteria

- Повторное открытие карты в тот же локальный день не создаёт новый След.
- Новый локальный день создаёт новый След.
- В одном `dayKey` не может быть больше одного Следа.
- Расклады на 3 и 5 карт не создают След и не попадают в сетку.
- После 7 последовательных `dayKey` создаётся один Дар.
- Дар создаётся с `pendingReveal: true`.
- При первом открытии экрана «История» / «Следы в лесу» reveal проигрывается и `pendingReveal` сбрасывается.
- Изменение текста карты не влияет на уже сохранённые Следы.
- Изменение названия карты не влияет на уже сохранённые Следы.
- Архивный артефакт использует только данные из `snapshot`.
- Если Следов нет, отображается пустое состояние с переходом к Колоде.
- Flip-анимация Даров учитывает `prefers-reduced-motion`.
- UI не показывает progress bar, streak counter, XP, уровни, пустые слоты или `собрано X/Y`.

---

## 23. Что не делать

Не показывать:

- progress bar;
- streak counter;
- достижения;
- XP;
- уровни;
- собрано X/Y;
- пустые слоты;
- календарные пропуски.

Не использовать achievement language.

Не превращать экран в журнал активности.

Не превращать Дары во вторую колоду.

Не превращать WYRD в приложение привычек, self-help сервис или эзотерический трекер.
