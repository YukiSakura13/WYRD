# WYRD — модель Следов и Даров

Статус: активный продуктовый и state-контракт.

Этот документ сохраняет только действующие доменные правила механики «Следы в
лесу» и Даров. Визуальная реализация подчиняется Silver UI Kit,
`WYRD_UI_FOUNDATIONS.md` и `WYRD_UI_COMPONENT_MAPPING.md`.

## След дня

- След создаётся из первого одиночного чтения, открытого через Колоду в текущий
  локальный день пользователя.
- В одном `dayKey` может существовать только один След.
- Повторные одиночные чтения в тот же день не создают новые Следы.
- Расклады на 3 и 5 карт не создают След и не попадают в историю Следов.
- Активная история хранит записи последних трёх месяцев; более старые записи
  удаляются при нормализации состояния.

## Локальный день и snapshot

- `dayKey` имеет формат `YYYY-MM-DD` и вычисляется по локальной календарной дате,
  а не через UTC-срез `toISOString()`.
- Вместе со Следом сохраняется IANA `timezone` пользователя.
- Фаза луны вычисляется один раз при создании Следа и сохраняется в записи.
- След хранит snapshot имени карты, Послания и Тени. Последующие изменения
  карточного контента не должны менять уже сохранённый След.

## TrailEntry

```ts
{
  id: string,
  dayKey: string,
  timezone: string,
  date: string,
  cardId: string,
  question: string,
  moonPhase: "nm" | "wc" | "fq" | "wg" | "fm" | "wag" | "lq" | "wac",
  snapshot: {
    cardTitle: string,
    oracleMessage: string,
    shadowMessage: string
  }
}
```

## Дары

- Один Дар создаётся после каждых семи последовательных локальных `dayKey` в
  текущей серии Следов.
- Новый Дар создаётся с `pendingReveal: true`.
- После первого показа раскрытия `pendingReveal` сбрасывается.
- Механика Даров не управляет DOM напрямую; UI только отображает состояние.

```ts
{
  id: string,
  receivedAt: string,
  giftKey: string,
  pendingReveal: boolean,
  schemaVersion: number
}
```

## Границы продукта

Интерфейс не показывает streak counter, progress bar, XP, уровни, календарные
пропуски, пустые слоты или «собрано X/Y». Следы и Дары поддерживают тихое
возвращение, но не превращают WYRD в трекер привычек или экономику достижений.

## Источники реализации

- `assets/js/state/model.js` — нормализация, локальный день, snapshot, retention
  и создание Даров;
- `assets/js/state/storage.js` — хранение состояния;
- `assets/js/ui/render.js` и `assets/js/ui/actions.js` — отображение и раскрытие;
- `PRODUCT_SURFACE_MAP.md` — маршруты и статус поверхности;
- `WYRD_UI_COMPONENT_MAPPING.md` — соответствие Silver-компонентам.

Историческое полное ТЗ с отклонённым визуальным слоем сохранено в
`archive/docs/legacy-specs/Экран История — ТЗ v6.1.md` и не является источником
текущего UI.
