# WYRD — «Да или нет»: контракт ритуального ответа

Статус: утверждённый продуктовый контракт, распределение карт и локальный UI-кандидат; индивидуальные строки находятся на редакторском ревью.

Linear: [YUK-147](https://linear.app/yukisakura/issue/YUK-147/p1-realizovat-polnocennyj-ekran-da-ili-net)

## Назначение

«Да или нет» — приватный локальный ритуал WYRD. Пользователь держит задуманное при себе, касается колоды и получает короткий бинарный знак через одну утверждённую карту.

Механика не является предсказанием неизбежного исхода, не знает содержание невведённого вопроса и не принимает решение за пользователя.

Плитка на экране «Лес»:

- название: `Да или нет`;
- подпись: `короткий знак`.

## Вход и приватность

- Поля вопроса нет.
- Текст вопроса не создаётся в DOM, runtime-state, storage или аналитике.
- AI, API и сетевой запрос не используются.
- Вопрос остаётся у пользователя.
- Результат v1 не добавляется автоматически в «Следы», Дары или историю обычных раскладов.

## Редакторская копия

### Одноразовая контекстная подсказка

> Задумай то, что хочешь сделать.
>
> Духи Леса ответят через карту.

Подсказка:

1. показывается только при первом входе в механику;
2. оформляется как неблокирующая контекстная поверхность над колодой, а не постоянный веб-абзац;
3. закрывается действием `Понятно` или первым осознанным касанием колоды;
4. не считается просмотренной только из-за render: если пользователь уйдёт, не закроет её и не коснётся колоды, она появится снова;
5. после закрытия хранит только версионированный ID подсказки, без содержания задуманного и результата;
6. не меняет геометрию утверждённой Deck Composition.

### Ответ `open`

> Да.

> Сегодня стоит осуществить задуманное.

После общей строки показывается индивидуальная строка выпавшей карты.

### Ответ `hold`

> Нет.

> Сегодня лучше не спешить. Дай замыслу время и проверь его ещё раз.

После общей строки показывается индивидуальная строка выпавшей карты.

### Постоянная граница

> Знак не выбирает за тебя.

## Карточный контракт

Существующее поле `tone` не определяет бинарный ответ.

Для участвующих карт вводится отдельный паспортный контракт:

```js
ritualAnswer: {
  direction: "open", // open | hold
  line: "Индивидуальная строка карты.",
  rationale: "Редакторское обоснование направления."
}
```

- `direction` стабильно закрепляется за картой и не зависит от её новой иллюстрации.
- `line` пишется вручную после утверждения распределения.
- `rationale` сохраняет редакторскую логику и может не показываться пользователю.
- Все 74 текущие карты получили утверждённое направление: 37 `open` и 37 `hold`.

## Выбор результата: shuffle bag

Утверждённый принцип — **shuffle bag, «перемешанная колода без возврата»**.

1. В начале цикла все 74 ID утверждённых карт один раз перемешиваются алгоритмом Fisher–Yates. Случайные значения берутся из `crypto.getRandomValues()`; `sort(() => Math.random() - 0.5)` не используется.
2. Каждый новый ритуал берёт следующую карту из сохранённой очереди. Использованная карта не возвращается в очередь до завершения цикла.
3. Стабильное поле `ritualAnswer.direction` выпавшей карты определяет `Да` или `Нет`.
4. Выбранная карта и её направление блокируются до завершения текущего ритуала.
5. Ошибка загрузки арта повторяет загрузку той же карты и не расходует следующую карту.
6. Повторное касание раскрытой карты, double tap и повторный render не изменяют ответ и не расходуют следующую карту.
7. Вернуться в состояние готовой колоды можно только отдельным действием `Задать другой вопрос`. Следующая карта расходуется только при новом намеренном касании готовой колоды.
8. После использования всех 74 карт создаётся новый независимо перемешанный цикл. Если первая карта нового цикла совпала с последней картой предыдущего, она меняется местами с другой картой нового цикла, поэтому одинаковая карта не выпадает два раза подряд даже на границе циклов.

В пределах одного полного сохранённого цикла пользователь увидит каждую из 74 карт ровно один раз: 37 `open` и 37 `hold`. Порядок остаётся случайным и не обязан чередовать `Да` и `Нет`; точные 50/50 достигаются на полном цикле, а не на любом его коротком отрезке.

### Локальное техническое состояние

Для продолжения цикла между сессиями хранится только версия колоды, очередь ещё не использованных ID и ID последней карты:

```js
{
  deckVersion: 1,
  remainingCardIds: ["wyrd_042", "wyrd_017"],
  lastCardId: "wyrd_063"
}
```

- Состояние хранится локально и не содержит вопрос, текст намерения, результат `Да` / `Нет`, дату или историю ритуалов.
- При изменении состава колоды `deckVersion` повышается, а очередь безопасно создаётся заново.
- Очистка локальных данных начинает новый цикл; продукт не обещает сохранить очередь после удаления storage.

## Состояния экрана

### 1. Вход

- стандартный внутренний App Header: Back и `Да или нет`;
- одноразовая контекстная подсказка над колодой;
- после первого закрытия или использования колоды постоянной вводной инструкции нет;
- без логотипа WYRD и без поля вопроса.

### 2. Колода готова

- утверждённая Deck Composition;
- утверждённая Raven card back без фильтров и перерисовки;
- подпись `Коснись колоды`;
- вся интерактивная область колоды работает как одна кнопка.

### 3. Раскрытие

- короткий press-depth;
- отделение верхней карты;
- канонический Ritual Reveal по оси Y;
- смена рубашки на исходный арт карты в середине переворота;
- после раскрытия движение полностью успокаивается.

### 4. Ответ

Порядок контента:

1. лицевая карта;
2. название карты;
3. `Да` или `Нет`;
4. общая строка направления;
5. индивидуальная строка карты;
6. действие `Задумать другое действие`;
7. `Знак не выбирает за тебя`.

Карта остаётся главным артефактом. `Да` и `Нет` не должны превращаться в гигантские декоративные слова.

### 5. Новый вопрос

- Новый draw доступен только через отдельное действие `Задумать другое действие`.
- Формулировки `Попробовать ещё раз`, `Перебросить` и `Спросить снова` не используются.
- Продукт не утверждает, что способен распознать повторение того же невведённого вопроса.

## Accessibility и recovery

- Колода — один `button`, доступный по Enter и Space.
- Декоративные задние карты скрыты от accessibility tree.
- Одноразовая подсказка имеет `role="note"`, не создаёт focus trap и связывается с колодой через `aria-describedby` только пока видима.
- Действие `Понятно` имеет touch-area не меньше `44 × 44 px` и после закрытия возвращает фокус на колоду.
- Ответ всегда написан словами и не кодируется только цветом или иллюстрацией.
- Итог объявляется через `aria-live="polite"`.
- После раскрытия фокус не теряется.
- При `prefers-reduced-motion` flip заменяется короткой сменой прозрачности с тем же результатом.
- Ошибка арта сообщает название карты и предлагает загрузить её повторно без изменения ответа.

## QA shuffle bag

До подключения экрана selector должен пройти отдельные автоматические проверки:

- полный цикл содержит 74 уникальных ID без пропусков и повторов;
- полный цикл содержит ровно 37 `open` и 37 `hold`;
- новый цикл создаётся только после исчерпания предыдущего;
- последняя карта старого и первая карта нового цикла не совпадают;
- reload восстанавливает оставшуюся очередь, а не начинает новый цикл;
- double tap, повторный render и ошибка арта не изменяют очередь;
- повреждённое или устаревшее состояние storage безопасно сбрасывается по `deckVersion`;
- ни в storage, ни в аналитике не появляется содержание задуманного или история ответов.

## Safety

- Механика не гарантирует будущий исход.
- Она не используется как основание для медицинских, юридических, финансовых или связанных с безопасностью решений.
- Карточная строка не подтверждает мысли, чувства или намерения другого человека.
- Метафора карты не становится буквальным призывом к риску.
- Окончательный выбор остаётся у пользователя.

## Границы первой версии

В v1 не входят:

- AI-интерпретация;
- поле вопроса;
- обычный `createReading()`;
- автоматическое сохранение в историю;
- Следы, Дары, share/export;
- повторный draw по касанию раскрытой карты;
- лунная дата или фаза.

## Порядок реализации

1. Собрать и показать локальный preview состояний и motion на канонических компонентах без production selector.
2. После визуального одобрения написать и утвердить индивидуальные строки всех 74 карт.
3. Только затем добавить `ritualAnswer` в паспорта и обновить формальную карточную схему.
4. Создать отдельный локальный shuffle-bag selector и его версионированное техническое состояние.
5. После отдельного одобрения обновить Silver UI Kit и подключить production runtime.
6. Провести responsive, accessibility, reduced-motion, offline и recovery QA.
7. Коммитить и отправлять visual/runtime-реализацию только после отдельного подтверждения.
