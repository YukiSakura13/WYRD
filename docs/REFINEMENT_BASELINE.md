# WYRD Refinement Baseline

## Назначение

Этот документ фиксирует текущее рабочее поведение `WYRD` перед полировкой и рефакторингом.

Его задача:

- сохранить продуктовые сценарии во время чистки кода;
- быстро проверять регрессии после каждого этапа roadmap;
- не спорить "как было", а опираться на зафиксированный baseline.

## Ключевые сценарии

После каждого заметного рефакторинга нужно проверить:

1. Открывается cover-screen с рабочими кнопками.
2. Кнопка `Войти в лес` переводит пользователя к экрану колоды.
3. Кнопка `О WYRD` открывает «Книгу леса», а Back возвращает фокус на исходную кнопку.
4. Кнопка `Повторить знакомство` открывает onboarding-сцену без сброса пользовательского прогресса.
5. `#about-wyrd` и section hashes открывают страницу напрямую; повтор знакомства не меняет persistent state.
6. Кнопка `История` открывает профиль/историю.
7. Кнопка `Звук` переключает состояние звука на cover и внутри приложения.
8. Вопрос можно ввести в текстовое поле колоды.
9. Нажатие на колоду открывает бесплатную карту.
10. После первой карты доступны `углубление`, дополнительные сценарии и возврат к новому вопросу.
11. `Расклад на 3 карты` открывается и позволяет выбирать карту внутри расклада.
12. `Расклад на 5 карт` открывается и показывает голос оракула.
13. `Профиль / история` показывает список ранее открытых одиночных чтений.
14. `Поделиться картой` не ломает экран результата даже если Web Share API или `html2canvas` недоступны.
15. `Очистить локальные данные` возвращает приложение к начальному состоянию.
16. После push на GitHub Pages сайт получает свежую версию HTML/CSS/JS.

## Состояния, которые нельзя сломать

- `localStorage` использует ключ `wyrd-local-state-v2`.
- `currentReading` и `lastSpread` не должны быть активны одновременно.
- `dailyFreeUsedAt` контролирует только бесплатную карту дня.
- `history` хранит завершённые одиночные чтения.
- `soundEnabled` влияет и на cover controls, и на основной UI.

## Минимальный regression checklist

### UX

- Cover открывается корректно.
- Deck screen появляется без визуального застревания; на короткой высоте документ прокручивается до CTA и тихой подписи.
- Result screen рендерится с картой, текстом и тенью.
- Spread screen рендерится без пустого состояния.
- Profile screen открывается и закрывается без потери состояния.
- «О WYRD» показывает пять утверждённых секций; replay открывает onboarding, а Back возвращает на прежнюю позицию страницы.

### Visual baseline: «О WYRD»

- Cover action имеет видимый label и accessible name `О WYRD`.
- Mobile `<560px`: одна колонка, последовательные section cards и TOC без горизонтального scroll.
- Tablet/desktop `≥900px`: sticky TOC слева и prose-колонка не шире `--layout-content-copy`.
- На `320×568`, `390×844`, `768×1024`, `1280×720`, `1440×900` доступны Back, все пять секций и `Повторить знакомство`.
- При zoom 200% layout возвращается к одной колонке; текст, focus ring и CTA не обрезаются.
- Сцена не использует новые внешние изображения и сохраняет существующие цвет, типографику и контраст WYRD.

### Доступность

- Общая layout-проверка следует [RESPONSIVE_STRATEGY.md](/Users/marinamart/Desktop/Oracle_dev/docs/RESPONSIVE_STRATEGY.md).
- Кнопки доступны с клавиатуры.
- У интерактивных элементов есть видимый focus.
- Текст читаем на мобильной и десктопной ширине.
- На 320×568, 360×640 и 1280×720 deck не имеет horizontal overflow или clipped non-scrollable content.

### Публикация

- локальные smoke-checks проходят: `smoke-domain`, `smoke-state`, `smoke-about`, `validate_responsive_strategy`, `validate_about_page`, `prepare_pages`, `validate_pages_artifact`
- `index.html` публикуется с актуальным `wyrd-build`.
- `main.js`, `styles.css`, `manifest.webmanifest`, `sw.js` приходят с актуальной versioned query string.
- После обновления GitHub Pages сайт не застревает на старой версии.

## Правило использования

- Любой крупный этап roadmap считается завершённым только после ручного прогона этого checklist.
