# WYRD Refinement Baseline

## Назначение

Этот документ фиксирует текущее рабочее поведение `WYRD` перед полировкой и рефакторингом.

Его задача:

- сохранить продуктовые сценарии во время чистки кода;
- быстро проверять регрессии после каждого этапа roadmap;
- не спорить "как было", а опираться на зафиксированный baseline.

## Ключевые сценарии

После каждого заметного рефакторинга нужно проверить:

1. Открывается cover-screen с рабочими кнопками.
2. Кнопка `Войти в лес` переводит пользователя на главный экран «Лес».
3. «История духов леса» открывает пять иллюстрированных глав, а Back возвращает в «Лес».
4. Кнопка `Звук` переключает состояние звука на cover и внутри приложения.
5. Вопрос можно ввести в текстовое поле колоды.
6. Нажатие на колоду открывает бесплатную карту.
7. После первой карты доступны `углубление`, дополнительные сценарии и возврат к новому вопросу.
8. `Расклад на 3 карты` открывается и позволяет выбирать карту внутри расклада.
9. `Расклад на 5 карт` открывается и показывает голос оракула.
10. `Профиль / история` показывает список ранее открытых одиночных чтений.
11. `Поделиться картой` не ломает экран результата даже если Web Share API или `html2canvas` недоступны.
12. `Очистить локальные данные` возвращает приложение к начальному состоянию.
13. После push на GitHub Pages сайт получает свежую версию HTML/CSS/JS.

## Состояния, которые нельзя сломать

- `localStorage` использует ключ `wyrd-local-state-v2`.
- `currentReading` и `lastSpread` не должны быть активны одновременно.
- `dailyFreeUsedAt` контролирует только бесплатную карту дня.
- `history` хранит завершённые одиночные чтения.
- `soundEnabled` влияет и на cover controls, и на основной UI.

## Минимальный regression checklist

### UX

- Cover открывается корректно.
- Deck screen появляется без визуального застревания; на короткой высоте документ прокручивается до CTA и тихой подписи.
- Result screen рендерится с картой, текстом и тенью.
- Spread screen рендерится без пустого состояния.
- Profile screen открывается и закрывается без потери состояния.
- «История духов леса» показывает пять иллюстрированных глав, стрелки, точки и рабочий возврат в «Лес».

### Доступность

- Общая layout-проверка следует [RESPONSIVE_STRATEGY.md](./RESPONSIVE_STRATEGY.md).
- Кнопки доступны с клавиатуры.
- У интерактивных элементов есть видимый focus.
- Текст читаем на мобильной и десктопной ширине.
- На 320×568, 360×640 и 1280×720 deck не имеет horizontal overflow или clipped non-scrollable content.

### Публикация

- локальные smoke-checks проходят: `smoke-domain`, `smoke-state`, `validate_responsive_strategy`, `prepare_pages`, `validate_pages_artifact`
- `index.html` публикуется с актуальным `wyrd-build`.
- `main.js`, `styles.css`, `manifest.webmanifest`, `sw.js` приходят с актуальной versioned query string.
- После обновления GitHub Pages сайт не застревает на старой версии.

## Правило использования

- Любой крупный этап roadmap считается завершённым только после ручного прогона этого checklist.
